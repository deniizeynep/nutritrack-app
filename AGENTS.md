## Project overview

NutriTrack is a React Native + Expo + TypeScript mobile app with a Node.js backend.

- **Mobile** (root): Expo 56 + expo-router + React 19.2 + TypeScript. Entry: `expo-router/entry`. Routes in `app/`, shared code in `src/`.
- **Backend** (`server/`): Express 5 + Prisma 7 + PostgreSQL. CommonJS output. Deployed to Render; database on Neon.

## Git & branch workflow

- `main` branch is protected — never commit directly.
- Every task (feature, fix, test, refactor, docs, chore) lives on its own branch.
- Branch naming conventions (lowercase, kebab-case):
  - `feature/<short-description>`
  - `fix/<short-description>`
  - `test/<short-description>`
  - `refactor/<short-description>`
  - `docs/<short-description>`
  - `chore/<short-description>`
- Only files relevant to the current task should be changed. No drive-by refactors, renames, dependency bumps, or unrelated style changes.

## Validation commands (mobile)

```bash
npm run lint            # ESLint 9 flat config via expo lint
npx tsc --noEmit        # typecheck (not in package.json scripts)
npm test -- --runInBand # Jest (if configured — not currently present)
```

No test runner is configured for the mobile app today. If tests are added, validate with the command above.

## Validation commands (server)

```bash
cd server
npm run build           # tsc → dist/
npm run test:smoke      # curl-based smoke test (needs running server)
```

Server has no unit test framework. Smoke tests are shell scripts hitting the live API.

## Validation gate

- Lint, typecheck, and tests must all pass before committing.
- If a check fails, fix the task-related issue first. Do not commit with known failures.
- Pre-existing unrelated failures should be reported to the user without committing.

## Commit conventions

Commits must follow Conventional Commit format in English:

```
<type>(<scope>): <description>
```

Types: `feat`, `fix`, `test`, `refactor`, `docs`, `chore`

Examples:
- `feat(auth): add Google Sign-In button`
- `fix(meals): prevent duplicate meal entries`
- `chore(opencode): add task workflow command`

- Do not push, merge, or force-push without explicit user approval.
- After each task, report: branch name, root cause, changed files, validation results, commit message, and commit hash.

## Path aliases

- `@/*` maps to `./src/*`
- `@/assets/*` maps to `./assets/*`

Both defined in `tsconfig.json`.

## Key conventions

- **State management**: Zustand stores in `src/stores/` (appStore, authStore, mealStore, goalStore, aiUsageStore).
- **i18n**: Single `src/i18n/translations.ts` file. Turkish and English. Use `translate(key, language)` helper.
- **Theme**: `src/theme/theme.ts` exposes `getTheme(mode)` with `colors.*`. Dark/light via `appStore.themeMode`.
- **API client**: `src/config/api.ts` reads `EXPO_PUBLIC_API_URL`, falls back to production Render URL. Services in `src/services/`.
- **Google Sign-In**: Requires standalone APK/EAS build, not Expo Go.
- **Prisma client output**: `server/generated/prisma` (custom path), not default `node_modules/.prisma`.
- **React Compiler**: Enabled via `experiments.reactCompiler: true` in `app.config.js`.
- **Typed routes**: Enabled via `experiments.typedRoutes: true`.

## Server API routes

All under `/api/`: `auth`, `meals`, `goal`, `barcode`, `ai`, `health`.

## Environment variables

- **Mobile** `.env` (gitignored, see `.env.example`): `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID`.
- **Server** `server/.env` (gitignored, see `server/.env.example`): `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGIN`, `AI_PROVIDER`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, Brevo email OTP vars.

## Build APK

```bash
npx eas build -p android --profile preview
```

Preview builds set `APP_VARIANT=preview` → package name `com.zeynepdeniz.nutritrack.preview`. Production: `com.zeynepdeniz.nutritrack`.

## Gotchas

- `android/` and `ios/` are gitignored — generated by `expo prebuild` / EAS.
- Server uses Express 5 (`^5.2.1`) — API differs from Express 4.
- Server `prisma.config.ts` loads `dotenv/config` — must run from `server/` directory.
- `.env` at repo root contains live credentials. Never commit or echo it.
